# Webhook固定16字段平铺JSON

Webhook每次只接收一条记录，字段名和顺序固定。全部字段都是字符串；有值填值，没有值填字符串`"null"`，不得出现JSON null、数字、布尔值、数组或嵌套对象。

```json
{
  "标题": "凤阳县人民医院过敏原检测试剂采购公告",
  "项目编号": "WTYZSZC25-203-04",
  "单位": "凤阳县人民医院",
  "地区": "安徽省凤阳县",
  "所属省/市": "安徽",
  "所属大区": "华中大区",
  "发布时间": "2026-08-23",
  "截止时间": "2026-08-30T09:00",
  "预算": "985000",
  "采购方式": "公开招标",
  "科室": "医学检验科",
  "命中关键词": "过敏原、特异性IgE",
  "内容（检索的摘要）": "凤阳县人民医院拟采购过敏原检测试剂，预算98.5万元。",
  "链接": "https://example.gov.cn/tender/123",
  "医院全名": "凤阳县人民医院",
  "医院等级": "二级甲等"
}
```

## 字段定义

| 字段 | 填写规则 |
|---|---|
| 标题 | 由管线绑定（接口 `title`）；必填 |
| 项目编号 | **管线绑定**（接口 `bid_no`）；接口为空时填`"null"`，不得用标讯ID、包号或链接参数拼凑 |
| 单位 | **管线绑定**（接口 `caller_name`），即采购人；代理机构在 `agency_name`，不填这里 |
| 地区 | **管线绑定**（接口 `province`+`city`+`county`），输出为省级全称开头，例如`安徽省凤阳县` |
| 所属省/市 | **管线绑定**（接口 `province`），归一为省级行政区或直辖市简称 |
| 所属大区 | 按省份自动映射；省份未知时填`"null"` |
| 发布时间 | **管线绑定**（接口 `pub_time`），`YYYY-MM-DD` |
| 截止时间 | **管线绑定**（接口 `tender_time`），投标或响应文件提交截止；接口的 `signup_time` 是报名截止，只进摘要，不进本字段 |
| 预算 | **管线绑定**（接口 `money`，单位已是元），数字字符串，不带逗号与单位 |
| 采购方式 | **管线绑定**（接口 `bid_method`） |
| 科室 | 管线先从正文抽明确科室；抽不到时可由模型补，需给正文证据；未披露填`"null"` |
| 命中关键词 | **管线绑定，不接受`"null"`，不由模型改写。**取品类信号在公告里命中的原文片段，扩到标的物清单条目的完整写法（`过敏原检测`而不是`过敏`，`抗磷脂酶A2受体抗体IgG`而不是`PLA2R`），剥掉采购人名与「采购/项目/试剂盒」等语境词；多个命中用`、`分隔，最多6个。宽片段（`细胞因子`、`风湿`）排在最后。品类信号非空是入队前提，所以这个字段结构上不会为空 |
| 内容（检索的摘要） | 主检索来源返回的摘要或预览，最多2000字，由管线绑定；不得由模型改写 |
| 链接 | 由管线绑定；优先用接口 `get_bid_detail` 返回的 `source_url`（原始站点，匿名可访问），拿不到才退回知了站内链接；必填 |
| 医院全名 | 本地医院索引匹配后的标准名称；索引未匹配但原文明示全名时可保留并给证据 |
| 医院等级 | 只能来自本地医院索引的唯一匹配；无等级、同名歧义或等级冲突时填`"null"` |

## 医院索引

- 运行索引：`data/hospitals.min.json.gz`，50,599条，保留名称、别名、省、市、区县、等级。
- 原始工作区另有六字段可查看副本；运行包只保留压缩索引，避免体积膨胀。
- 匹配器：`scripts/hospital_match.py`。
- 只接受名称或别名的确定性匹配；同名单位必须由省、市或区县消歧。
- `explicit`（单位/医院全名精确命中）不再被 geo hint 硬否决：模型填的`地区`与索引行政区划不一致时（如`平坝区` vs 索引旧名`平坝县`），explicit 命中仍生效，同名消歧交给 grouped 阶段；`text` 来源的 geo 预过滤保持不变。
- 索引未匹配先查索引是否收录（`python3 -c` 检索 `records` 的 `n`/`a` 字段），不要默认 null 合理；官方简称与索引名差后缀时（如`新疆医科大学第二附属医院` vs 索引`…七道湾医院`）给索引条目加`|`分隔别名并重建 gz（先备份）。
- 仓库为开发来源，只在`dist/`发布最新分发产物，不自动安装新技能。升级时保留生产环境的长期台账。
- 数据库中的`未知`、`民营医院`等非等级值已清空；Webhook输出为`"null"`。

## 运行时证据

`evidence`只保存在批次结果中，不进入Webhook。必须含：

- `source_verified`：是否实际访问了候选链接；
- `checked_at`：含时区的ISO 8601时间；
- `field_evidence`：网页核实字段的文本证据；
- `hospital_match`：管线自动写入的医院匹配方法、匹配键和冲突信息。

`SOURCE_BOUND_FIELDS`（项目编号、单位、地区、所属省/市、截止时间、预算、采购方式）由管线从接口结构化字段直接绑定并自动附证据，模型不必提取。模型可以覆盖接口值，但**必须给出该字段的正文证据**，否则覆盖不生效。科室与模型提供的医院全名没有字段证据时，管线保守改为`"null"`；医院索引自动补出的字段不需要模型重复举证。管线会把`所属省/市`统一归一化为`安徽`、`广西`、`北京`等简称，同时把`地区`统一为`安徽省凤阳县`、`广西壮族自治区南宁市`、`北京市朝阳区`等带省级全称的值。省份无法识别时，不保留孤立市县名。

## seen.json内部字段

成功推送后，`seen.json`保存业务字段与以下下划线字段；下划线字段绝不进入Webhook：

- `_candidate_id`
- `_first_seen`
- `_last_seen`
- `_pushed`
- `_found_by_query`

`内容（检索的摘要）`**不入台账**（`tender_pipeline.SEEN_OMITTED_FIELDS`）：它曾占台账体积
近四成，而去重只用`标题`、`链接`、`发布时间`、`单位`四个字段，摘要一个字节都用不上。
`record_push`的重复判定用「字段不在旧记录里就按一致处理」兜底，因此缺这个字段不会
让重复推送误判成「内容不同」。

台账长期保留，不按公告日期裁剪。飞书导入、身份匹配、发送前查重、未知结果核对与升级步骤统一见[去重与发送登记](dedup.md)。

候选的`bid_id`、`_identity_urls`、`_identity_ids`与`content_access`均不进入Webhook。
`_identity_urls`和`_identity_ids`保留同一公告的不同来源身份；`identity_discriminator`只用于隔离正文文件，不能代替业务去重。
新发送记录的摘要不入台账。`seen.json.deliveries`保存发送占位及结果，不能通过删除它来重试未知请求。
