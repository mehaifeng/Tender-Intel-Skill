## 检索 Query 清单

睿销（jrbx）与 CCGP 共用本清单，两者都是全文检索。**规则是「表里一行一条 query」**，
项目代号一律进检索，不做取舍。每条是一个不含空格的词（CCGP 的接口不支持多词）。

**写法按 2026-09-03 实测定**（睿销 30 天窗口的 `totalCount`；CCGP 同批抽测，行为一致）。
两个库都是**长复合词命中骤降、短片段是超集**：`IgG亚类` 睿销 0 / CCGP 0，`亚类` 睿销 7 /
CCGP 2；`免疫印迹仪` 33 / 0，`免疫印迹` 81 / 3；`类风湿关节炎` 5 / 0，`类风湿` 62 / 1。

因此取词规则是 **每行放宽到还能指代该项目的最短片段**，宁可多捞、由核实阶段的模型判掉：
`红斑狼疮` 1 → `狼疮` 11、`谷氨酸脱羧酶` 12 → `脱羧酶` 16、`食物不耐受` 1 → `不耐受` 5、
`变应原` 5 → `变应` 16、`免疫印迹仪`+`蛋白印迹仪` 50 → `印迹` 128、`类风湿` 62 → `风湿` 107、
`25羟基` 41 → `羟基维生素` 49、`硬皮病`+`系统性硬化` 0 → `硬皮` 8。

前缀合并同时省掉了大量重复请求：15 个 IL 代号 → `IL-` 一条（90）、`IFN-α`+`IFN-γ` → `IFN`
（15）、`Scl-70`+`PM-Scl` → `Scl`（14）、`Dsg1`+`Dsg2` → `Dsg`（38）、`TNF-α` → `TNF`（33）。
清单因此 104 → 86 条，召回却更宽。

**放宽也有下限**，这四个实测证明会淹没结果，保持原写法：`硬化` 8389（动脉硬化、硬化路面）、
`胰岛` 425（胰岛素药品）、`磷脂` 104（磷脂酶、卵磷脂）、`SS-` 278。另外 `His` 361／`Sm` 97／
`RF` 97／`IF` 24 这类两三字母代号命中的基本是英文碎片，一律改用表里给出的中文全称。

被另一条严格包含的写法不单列（子串匹配下纯属重复请求）：`sIgE` ⊂ `IgE`、`食物特异性IgG`

### 能不能合并成更少的 query：不能（2026-09-03 实测）

`python scripts/jrbx_search.py --probe-keyword-syntax` 打 7 次 `pageSize=1` 的最小检索
（不消耗回源配额），30 天窗口结果：

| 写法 | totalCount |
|---|---|
| `["过敏原"]` | 133 |
| `["自身抗体"]` | 75 |
| `["过敏原","自身抗体"]`（数组 = AND） | 5 |
| `["过敏原 自身抗体"]`（单串空格） | 5 |
| `["过敏原\|自身抗体"]`（单串竖线） | 5 |
| `["过敏原 OR 自身抗体"]` | 0 |
| `["过敏原+自身抗体"]` | 0 |

**没有并集写法。** 空格和竖线都只是分词符，分完仍取交集；`OR` 被当成第三个词一起 AND
所以归零；`+` 根本不是分隔符，整串当一个词搜，也归零。**清单只能一行一条**，压不下去；条数只能靠上面的前缀合并降（104 → 85）。

顺带测出的引擎行为：**精确子串匹配**（`IgG亚类` 0 / `亚类` 7 / `IgG` 218），这决定了上面
「每行取最短写法」的取词规则。列表接口的计数字段是 `totalCount`，不是 `total`。

CCGP 的接口同样不支持多词，恒为一行一条。

## 候选筛选

候选正文（标题 + 摘要 + 公开正文）必须命中两张表里的至少一个词，否则丢弃。判据实现在
`scripts/search_common.py` 的 `TARGET_CATEGORY_PATTERNS`，三个来源共用一份，分组即两张表
的谱系划分。**表里的项目代号全部在这一层生效**——整批招采公告的目标品类往往只出现在
正文的清单行里。

拉丁代号的边界不能用 `\b`：中文也是 `\w`，`\bANCA\b` 在「抗ANCA抗体」里两侧都不成立。
统一用只挡英文字母和数字的前后瞻，代号可以紧贴汉字，同时不会命中 `ANALYZER` 里的 `ANA`。

## 排除词

命中即判无关，**优先级高于上一节**（同时含目标词也排除）。定义在 `search_common.py` 的
`EXCLUDE_TERMS`，三个来源共用：

- 公司不做的品类：`酶标仪`、`电泳`
- 同名异域：兽医／兽用／动物／畜牧／生猪、结核与干扰素释放试验、免疫组化与二抗、
  重组蛋白／培养基／缓冲液等科研试剂、核酸／PCR／测序

另有一批「命中即大概率无效」的初筛词，由核实前预筛处理：服务、送检、食堂、员工体检、
职工体检、外送、配送。「单一来源」不在此列，按情报处理。

## 判定细则

- 标题必须有招标、采购、询价、磋商、谈判、中标、意向等明确招采／交易意图。
- 标题、检索摘要或搜索正文必须至少命中一个目标词。
- 只有「试剂一批」「医疗设备」等笼统描述、且其它内容没有目标词时自动筛除，不追附件。
- 单一来源、采购意向、中标、合同、更正及已截止公告仍可作为情报推送；缺失截止时间填 `"null"`。
- 备案年份明显过旧且页面无当前发布时间时排除。

## 清单维护

- 三个来源每天跑同一份清单，不轮换、不随机——命中数的变化才能直接归因于「有没有新公告」。
- 每条候选记 `found_by_query`（命中它的 query），只进 seen.json，**不进飞书载荷**。
- 每日按 query 写一行统计到 `data/query_stats.json`：`raw`（返回候选数）、`unique`
  （去重后仅由该条命中的 URL 数）、`pushed`（最终推送成功数）。
- 词表的增删以业务方给出的表为准，不由运行数据决定；`query_stats.json` 只用来发现
  「某条写法在库里根本搜不到东西」，据此换写法而不是删词。
