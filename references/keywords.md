> 2026-08-14 重构：由「6 泛化查询组 + 明细产品词」改为「分层词表（A/B/C/D 层）+ 每日固定 46 条 Query 清单」；同日取消轮换机制，改为每天全量执行（理由见 §0）；业务方过敏原/自免/仪器三类关键词已并入；修正旧表"抗麦胶蛋白（DGP）"标注错误（抗麦胶蛋白抗体 = AGA，DGP 为脱酰胺麦胶蛋白肽，属不同项目）。

## 0. 使用总则（阶段 1 检索）

- 每日按「§5 每日 Query 清单」执行 **46 条**查询：A/B 层 23 条 + C 层长尾词 15 条 + D 层意图词全覆盖块 8 条。**每天完全相同——不轮换、不随机、不按星期挑组。**
- 豆包参数固定：`version=custom`、`auth_level=2`、`max_age_days=45`、`count=10`、`snippet_length=1000`（详见 SKILL.md 阶段 1）。
- 候选收集后**先按 `source_url` 跨查询去重**，再进入阶段 2——同一页面会被多条 query 同时命中，不去重则核实成本翻倍。
- 一手、第三方和聚合网站的可访问详情页都可作为候选；第三方/聚合网站的结果 URL 即为 `source_url`。
- **为什么不轮换**（2026-08-14 定）：轮换省调用量，代价是发现延迟——某个词组最长要等 6 天才轮到，而采购意向的全部价值就在提前量（提前 30 日发布，是唯一还能影响技术参数的窗口），6 天延迟是实打实的损失。固定全量还有第二个好处：**每天清单相同，命中数的变化只能归因于"有没有新公告"**，可以直接做日对比；轮换会让日间差异混入"今天换了组词"这个噪声，看不出趋势。代价是调用量由 24 升至 46。
- 本词表所有词**双重用途**：①组拼检索（§5）；②核实阶段品类匹配（§11 判定细则、阶段 4 `matched_category` 判定）。

## 4. Query 组拼规则

**意图词是领域开关，品类词是内容开关，两者缺一不可**。实证（2026-08-14 对照检索）：`过敏原特异性IgE 总IgE 检测试剂` 无意图词 → 召回医院科室科普文；加 `采购公告` → 召回中国政府采购网招标公告。没有意图词的 query，招标页排不进 top-N，等于漏采。

- **结构**：`[3~6 个语义相关品类词] + [意图词] + [可选年份 2026]`
- **意图词必带，无例外**——解决"不准"的第一道闸门（第二道 `auth_level=2`，第三道核实阶段排除词表 §6）。
- **意图词库**（拼在品类词之后，每条选一个）：
  - 主变体：`招标公告` / `采购公告` / `招标` / `采购`
  - 扩展变体：`询价公告` / `磋商公告` / `谈判公告` / `采购意向`——由 §3.2 的 D 层全覆盖块承担，**每个变体每天各跑 2 条**（试剂线 + 仪器线），不是备而不用的备选项
  - **变体分散使用**：不同站群用词习惯不同（政采网多"采购公告"、公共资源交易中心多"招标公告"、医院官网多"采购"），全清单统一成一个词会漏站群；但同一条 query 只用一个意图词，不堆砌。
- **执行前校验**：逐条核对当天清单每条 query 末尾是否含意图词；缺失的补 `采购公告` 再执行。
- **同组拼、跨组不拼**：同谱系词可共存一条 query；跨谱系（狼疮谱 + 自免肝谱）不混拼，避免信号稀释。**唯一例外是 D 层全覆盖块**（§5 第 39~46 条）：这 8 条用的是跨线泛化词，因为询价/磋商/意向类公告多为单位级多品类清单，泛化词不会稀释信号，反而提高单条命中的品类覆盖。
- **一条 query 品类词不超过 6 个**：超过时优先保留更具体的词，泛化词交给 A 层查询兜底。
- **变体补查**：错写变体（过敏源）与同义变体（变应原/变态反应）平时并入主词 query；某条 query 连续数日零新命中时，用变体词单查一次补漏。这属**计划外的人工补查**，不计入每日 46 条，也不改变清单本身。
- **年份**：可加"2026"提精度；时效主要由 `max_age_days=45` 承担，年份不强制。

## 11. 判定细则

**品类匹配**：公告清单中出现上述细分类对应的具体品名（如"过敏原特异性IgE抗体检测试剂盒"→过敏原sIgE试剂；"全自动化学发光免疫分析仪"→化学发光免疫分析仪）即算命中。只写"试剂一批""生物试剂盒"等笼统表述的，`match_level: "unknown"`，不得臆断匹配。对照词用 §1~§3 全部分层词表。

**参与可行性**：

- 文件获取/报名截止已过但投标截止未过 → 参与窗口实际关闭，需在 notes 里注明（除非招标文件可直链下载，此时建议电话确认参与资格）
- 单一来源公示 → 不是投标机会，作情报（记 designated_supplier）
- 中标公告/供货合同公告 → 已成交，作情报（记 winner / award_amount，竞品与自家品牌中标均收）
- 投标截止已过的招标/采购公告 → **不剔除**，转研究流作情报（status: intel，notes 注明已截止；winner 填 "null"）
- 采购意向/招标意向等探索性公告 → 未正式招标、无投标窗口，转研究流作情报（status: intel）

**品牌与排除词**：核实前先用 §6 排除词表快速预筛（服务、食堂、体检、外送、配送类大概率无效，确认后剔除）；"单一来源"不按排除处理，转情报。公告清单中出现 §7 品牌词表内品牌时，按品牌词表规则在 notes 标注。

**旧记录识别**：备案编号年份早于当前年份较多（如 2019）且页面无发布日期/截止时间的，按旧记录剔除。
