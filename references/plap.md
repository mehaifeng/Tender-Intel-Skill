# 军队采购网检索适配器

仅在维护或诊断 PLAP 检索组件时读取本文件。适配器只读取军队采购网门户匿名公开的数据，不登录、不携带`access_token`或用户 Cookie，不访问登录后接口，也不尝试补全“用户登录后显示完整信息”的内容。

## 公开接口与失败判定

- 搜索页面：`https://www.plap.mil.cn/freecms/site/juncai/qwjsy/index.html`
- 适配器调用搜索页面自身使用的匿名公开 GET 接口，按标题、公告类型和发布时间筛选。
- 该接口不是官方承诺稳定的开放 API。返回码不是`200`、`data`不是数组、出现 HTTP 403/429、超时或结构漂移时，本来源停止本轮，不连续重试。
- 单域名单并发，默认请求间隔 1 秒，每页 20 条，单任务最多 100 页。
- 不生成或读取登录凭据；公开接口若将来要求登录，本来源应失败，而不是绕过登录限制。

## 时间与公开程度

PLAP 接口支持精确到秒的`operationStartTime`和`operationEndTime`。适配器中的`24h`表示从运行时刻向前滚动 24 小时；显式日期区间按本地自然日闭区间执行。

候选正文分为：

- `public_partial`：匿名接口返回了有意义的公开正文，但由于部分页面提示登录后显示更多信息，不声明正文完整；
- `metadata_only`：只有标题、发布时间、项目编号、地区等公开元数据。

两者都可以成为候选。`metadata_only`不得作为已核实正文，只能使用标题和公开元数据；所有缺失字段保守填`null`。

## 候选筛选层（宽召回的代价在这里付）

`screen_row()` 对每一行按顺序判两件事，**硬排除优先于品类信号**：

- 先判 `EXCLUDE_TERMS`（`search_common.py`，三来源共用）：命中 → 丢弃，理由记 `硬排除:<词>`；
- 再判 `TARGET_CATEGORY_PATTERNS`：一个都没命中 → 丢弃，理由记 `无目标品类信号`。

> **2026-09-03 修复**：此前 `row_to_candidate` 只判第 2 条。硬排除只在 `matched_target_terms`
> 里生效，而那个函数的返回值只用于 query 归因、不参与去留——结果是含「酶标仪」「化学发光」
> 的公告只要另有一个正向信号（比如 `免疫分析仪`）就照样进候选。硬排除对 PLAP 实际上是空转的。

`search_summary.json` 因此新增两个字段，用来判断宽词到底在贡献召回还是在刷量：

- `prefilter_excluded_by_reason`：丢弃构成，`{"硬排除:化学发光": n, "无目标品类信号": m}`；
- `query_survival`：逐词 `{"raw": 命中行数, "kept": 存活候选数}`。

`kept` 长期为 0 的宽词（`耗材`、`免疫`、`医用试剂` 是重点观察对象）按 keywords.md §12 裁撤。

**只有标题的候选怎么办**：PLAP 大量公告是 `metadata_only`（详情需登录），标题里只有
「检验试剂一批」这类笼统描述时，按 keywords.md §10 自动筛除，不追附件、不猜内容。
留下来的候选进核实阶段后，由模型按 references/verification.md 的产品域判断做最终取舍。

## 混合检索策略

默认`hybrid`策略由两部分组成：

1. 对上述标题 Query 逐条检索全部采购公告类型；
2. 对采购意向、采购需求、征集方案、征求意见和单一来源公示按时间枚举，再在本地检查公开正文中的目标品类信号。

第二部分用于补足“标题只写某医院试剂遴选、具体目标词在正文清单中”的漏召回。采购公告和结果公告日量较大，不做全量枚举。

## 匿名公开字段

优先使用接口直接返回的标题、发布时间、项目编号、地区、公告类型、摘要和正文。预算、采购方式、单位和截止时间只有在公开字段或公开正文存在明确标签时才提取，并记录`field_evidence`。登录后字段不得推测。

同一 PLAP 公告使用路径中的 32 位`noticeId`去重；URL 规范化时去掉仅用于页面路由的`noticeType`和`channel`参数。跨来源仍使用标题指纹及“项目编号 + 公告阶段”去重。PLAP 官方候选应优先于睿销（jrbx）等聚合来源的转载结果。
